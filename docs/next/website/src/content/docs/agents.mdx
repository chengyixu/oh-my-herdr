Herdr is built for running more than one coding agent at a time. Each agent stays in a real terminal pane with its shell, logs, prompts, and running processes intact. Herdr tracks which panes contain agents, rolls their state up to tabs and workspaces, and lets you jump straight to the pane that needs attention instead of polling every terminal by hand.

To coordinate agents from scripts or from another agent, see [Agent automation](/docs/agent-automation/).

## Activated terminal integrations

Ohmyherdr's **Integrations** settings are the source of choices in the profile editor and pane harness menu. Select a tool and activate or deactivate it with a click, Enter, or Space. The CLI exposes the same state:

```bash
ohmyherdr integration list
ohmyherdr integration activate opencode
ohmyherdr integration deactivate opencode
```

Installing a CLI and activating its integration are separate actions. Missing CLIs remain visible with an installation instruction, but cannot be activated. Existing installed hooks and saved profiles retain their availability during migration. An explicit deactivation takes precedence: it prevents future launches and revival without stopping a running process or deleting profiles and documents.

Profile fields follow the selected integration's capabilities. Where profile instructions are supported, the integration supplies the native launch arguments. Other tools use their native context settings; their saved profile documents stay in the cabinet and the editor labels this behavior. Press `i` in Integrations to install or repair supported status hooks independently of activation.

The terminal catalog includes the existing agents plus MiMo Code, StepCode, OmO, Goose, Crush, DeepSeek Harness, Command Code, Prime Agent, Empryo, Ante, jcode, CodeBuddy Code, AtomCode, Snow CLI, and Qoder CLI China. Desktop editors, browser agents, and gateways are excluded. Launch support does not imply a new screen detection manifest or lifecycle hook.

Managed launches use each integration's native automatic-approval defaults, including Claude's `--dangerously-skip-permissions`, Codex's `--dangerously-bypass-approvals-and-sandbox` and Grok's `--always-approve`. They apply to starts, saved-profile spawns, revivals, harness replacements and cold restores. Explicit arguments are retained and repeated native options are not added twice. Goose receives `GOOSE_MODE=auto` only in its own process. Credentials, providers, models and vendor configuration files stay under their native tools' control.

Factory Droid's interactive default is its maximum native `--auto high`; its full unsafe bypass belongs to headless `exec`. Native deny rules and vendor-enforced controls remain effective where the vendor's automatic mode keeps them. Harnesses without a permission flag keep their native execution model. Pi's `--approve` also accepts project-local configuration for that run.

If the client has been updated while a prior Ohmyherdr server is still running, Integrations shows **runtime upgrade required** and the older server's status hooks. Its harness picker has no activation choices until a supported live handoff moves the running panes to the new server. Run `ohmyherdr server live-handoff` from a regular terminal when ready; this changes the running server. In the legacy hook list, ↑/↓, mouse wheel, and row clicks move the selection; Enter installs the selected available hook and `i` installs all recommended hooks. On a current server, the same navigation selects terminal integrations and Enter activates or deactivates the selected CLI.

Click a saved agent in the **Agents** panel to open its launch menu. **Use space cwd** starts it in the selected space's tab directory; **Use agent native cwd** starts it in the profile's saved directory while keeping it in that space. The menu's **Native harness...**, **Edit profile**, and **Delete profile** entries are explicit management actions. The Settings `s` spawn shortcut uses the same launch request and follows the activated integration list.

The pane control shows the current process as `Harness: pi`. A supported harness replacement runs **inside that same pane**: the pane ID, terminal, shell, tab, layout and instance identity stay the same. It imports recorded native conversation history rather than sending a terminal excerpt as a new prompt. It creates no replica pane or Previous tab.

The first qualified complete-history adapter is Pi 1.1 native sessions into Codex 0.163. The updated Pi integration exports its exact active branch, current system context and attachments. The importer preserves messages from before compaction, full tool arguments/results and image bytes; it retains the original branch and context alongside the new native session. Pi's native SDK supplies the active model context. A separate native checkpoint preserves compaction and excluded diagnostics while leaving the complete recorded history available. Explicit context edits, opaque/redacted provider reasoning, invalid or unsupported images and unknown record types are rejected before closing the source. PNG, JPEG, WebP and GIF images are decoded within bounded limits before import; their original bytes are retained. The exchange has a 256 MiB limit and rejects oversize context without truncating it. Other integration pairs remain unavailable until their native export/import contracts are qualified; activation alone does not imply complete-history interchange.

The source must be idle with an empty editor and no queued messages or native blocker. After updating the server or Pi integration, run `/reload` in each already-running Pi session once to register its native exporter while keeping the current conversation. The native integration rechecks the session fingerprint immediately before graceful shutdown. The target then resumes the imported session in the existing shell. A failed import leaves the source running. A failed launch returns to the saved exact source branch when its shell is available; a native confirmation is left visible for the user. No exit keys or context prompts are sent to a confirmation dialog.

Replacement runs through the additive `agent.harness.replace` method. Older servers disable this action without falling back to the former split-pane flow. Registry format 6 retains a recovery record before the source is closed, and pending session snapshots restore the exact source until the target commits. Long integration menus scroll to keep the selection visible.

Codex pane launches and cold restores use `--no-daemon`, giving each pane its own native runtime and hook environment. The session integration reports a valid session ID even when Codex supplies a null transcript path. A current script without its SessionStart registration is marked outdated and can be repaired with `ohmyherdr integration install codex`. Review the specific changed hook in Codex before trusting it; no account or provider change is needed.

## Supported agents

Agents get Herdr support in one of two ways: Herdr supports them, or they support Herdr themselves. Either way you see each agent's `idle`, `working`, and `blocked` state, get notified when it finishes or needs you, and can wait on it from scripts.

Other agents still run normally in Herdr panes. They just show up as plain terminals.

### Supported by the agent

These agents report their own state to Herdr. There is nothing to install; run them in a Herdr pane.

- [Crush](https://github.com/charmbracelet/crush)
- Command Code
- Muse
- [Prime Agent](https://github.com/PrimeIntellect-ai/prime-agent)

An agent that also reports its resume command comes back in the same session after a Herdr server restart.

For native integrations, a retained pane also keeps its last accepted exact session reference after the native process exits or releases its live status. A cold server restart resumes that conversation even if the pane had returned to its shell. Recovery data does not mark the stopped agent as live and does not restart it during the running server session. Closing the pane removes its recovery reference. A newly accepted native conversation replaces the old reference; late or rejected reports do not.

Cold restore uses the saved native ID or file, never the latest session in a directory. If the saved working directory or exact native session file is missing, the pane retains the reference and reports the restore error instead of opening a new conversation. Set `[session] resume_agents_on_restore = false` to restore shells without resuming agents.

If you build a coding agent, [Add Herdr support to your agent](/docs/add-herdr-support/) shows how to join this list. It takes a few calls to Herdr's CLI or socket, and no change to Herdr.

## How status works

For agents Herdr supports, Herdr finds the agent's process in each pane and reads the live bottom of the pane, not the part you scrolled to. Rules in a detection manifest decide whether that screen means `idle`, `working`, or `blocked`. When an integration also reports state, Herdr uses those reports instead of reading the screen.

For agents that support Herdr, the agent's own reports decide the state.

## VMs and sandbox wrappers

On Linux and macOS, a host-visible wrapper can hide the real agent process from Herdr. Set `HERDR_AGENT=<agent>` on the wrapper command to tell Herdr which existing agent screen manifest to use. For example, run `HERDR_AGENT=claude fence -- claude` on Linux or `HERDR_AGENT=claude nono run --profile claude-code -- claude` on macOS. The hint applies only to that foreground process. Herdr cannot see it if you set it only inside a VM or container. Avoid exporting it globally unless every inherited foreground process should be treated as that agent.

Some restricted Linux runtimes do not expose a terminal foreground process group. Start the Herdr server with `HERDR_PROCESS_DETECTION=child-groups` to opt into direct child-process-group inference when native detection is unavailable. Native detection remains preferred, and the default `native` mode never performs this inference. The opt-in mode is best effort: a newer background job can be mistaken for the foreground job. The variable is read by the server and requires a restart; set it in the remote server environment rather than on an attaching client.

## Blocked state

Blocked detection is deliberately strict for screen-manifest agents. Herdr only marks `blocked` when the live bottom-buffer snapshot matches known visible approval, question, or permission UI. If no manifest rule matches for a known agent other than Codex, Herdr falls back to `idle` and labels that fallback as `default_known_agent_idle_fallback` in explain output. Codex falls back to `unknown` because its title and composer can look the same during an active turn and after a response.

For those other agents, unusual new prompts may initially show as `idle` instead of `blocked` until Herdr learns that screen shape. The misclassification affects only the visible status and waits. It should not make Herdr send input or take destructive action.

For Codex, a visible spinner or live activity timer can establish `working`, and a visible approval prompt can establish `blocked`. An ordinary title, composer, or missing spinner cannot establish that a turn ended. Codex may therefore stay `unknown` after a response, and waits for `idle` or completion may time out. Managed startup uses the initial composer only to determine when it can accept a prompt; that observation does not change turn status.

## Detection manifests

Bundled manifests live inside Herdr. Herdr also checks herdr.dev for remote manifest updates and applies valid per-agent rule updates automatically without requiring a Herdr restart. Remote manifests are stored in Herdr's state directory. Set `[update] manifest_check = false` to disable background remote manifest checks.

Local overrides can replace a remote or bundled manifest from the platform config directory:

```text
~/.config/herdr/agent-detection/<agent>.toml
```

Local overrides always win. Without a local override, Herdr uses the newer compatible manifest between the cached remote manifest and the bundled manifest in the running binary. On debug builds, the same config helper may use a development directory such as `herdr-dev`. Invalid override files are ignored with a warning and Herdr falls back to the cached remote or bundled manifest for that agent.

Remote manifests patch detection rules for agents Herdr already knows how to identify. Adding a completely new agent still requires a Herdr binary update for process detection, labels, and integration behavior.

The running server loads active manifests into memory on startup. Automatic remote manifest updates reload that in-memory cache after new rules are written. Run `herdr server update-agent-manifests` to fetch remote manifest updates immediately and reload the running server. After editing a local override manually, restart Herdr or run `herdr server reload-agent-manifests` to apply the file to the running server.

Use `herdr agent explain` when a pane shows the wrong state:

```bash
herdr agent explain <target>
herdr agent explain --file screen.txt --agent codex --json
```

Live explain is evaluated by the running server, so it reflects the active manifest cache. The explain output shows the agent, final state, whether screen detection was skipped by a full lifecycle authority, manifest source and version, cached remote version, local override shadowing, remote update status, matched rule, visible evidence flags, matcher and region evidence for evaluated rules, skipped-update reason for transcript viewers, and the idle fallback reason when no rule matched.

Herdr can run inside tmux as the outer terminal environment. Agent detection does not inspect tmux sessions launched inside a Herdr pane. If a shell framework auto-enters tmux inside Herdr, Herdr sees `tmux` as the pane process instead of the agent behind it.

If your shell automatically attaches to tmux whenever `TMUX` is unset, update its startup rule to exclude Herdr panes. Reattaching the outer tmux session from inside a Herdr pane can recursively shrink the terminal and make it flicker. Add the `HERDR_ENV` check to your existing condition before it runs tmux:

```zsh
if [[ -z ${TMUX:-} && ${HERDR_ENV:-} != 1 ]]; then
  tmux new-session -A -s my-session
fi
```

## State rollups

The sidebar rolls state upward.

A blocked agent makes its pane, tab, and workspace look blocked. A working agent makes the workspace look active. A done agent stays visible until you view it.

This is the main Herdr workflow: start several agents, let them work in parallel, and use the sidebar to see which project needs a decision, which one is still running, and which one is ready to review.

## Custom agent labels

You can rename an agent target for display:

```bash
herdr agent rename w1:p1 reviewer
herdr agent rename reviewer --clear
```

Targets accept a unique live agent name or the pane ID that currently hosts the agent. Terminal IDs and bare agent-kind labels are not accepted.

## Custom status labels

Integrations report lifecycle state as semantic state only. Add display customization separately with pane metadata tokens.

```bash
herdr pane report-agent w1:p1 \
  --source custom:indexer \
  --agent docs-bot \
  --state working

herdr pane report-metadata w1:p1 \
  --source custom:indexer-display \
  --token summary=indexing
```

`state` controls waits, notifications, and rollups. The `summary` token is display-only and can be used as `$summary` in an Agent sidebar row.

Agent sidebar rows can also opt into `terminal_title` or `terminal_title_stripped`; neither appears in the default rows. The first shows the latest safety-normalized OSC 0/2 terminal title. The second removes one recognized leading activity or spinner glyph and following whitespace. Herdr owns these values on the server; they are ephemeral across a cold restart and remain independent of metadata titles and semantic agent state. Spinner animation can therefore update the raw title without producing a pane update when the stripped text stays the same.

## Attach directly to an agent

Attach your current terminal to one agent terminal instead of the full Herdr UI:

```bash
herdr agent attach reviewer
```

Detach with `ctrl+b q`. Send a literal `ctrl+b` with `ctrl+b ctrl+b`.

Scroll with the mouse wheel or plain page up/page down. Normal input jumps back to the bottom.

Use `--takeover` if another direct attach client already owns input:

```bash
herdr agent attach reviewer --takeover
```

Use `herdr terminal attach <terminal_id>` when you want the same direct attach behavior for a non-agent terminal.
